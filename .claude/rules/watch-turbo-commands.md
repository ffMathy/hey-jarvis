# TURBO Commands

> Part of [Wear OS App](watch.md). Paths in it are relative to `watch/` unless they say otherwise.

```bash
bunx turbo typecheck --filter=watch   # tsgo
bunx turbo lint --filter=watch        # biome
bunx turbo build:apk --filter=watch   # dist/watch-apk/jarvis-watch.apk (needs JDK 17+ and the Android SDK)
```

There is no `build` and no `test`, on purpose. CI's `turbo build` runs in a dev container with no Android SDK, so the APK is built by the **Wear APK** workflow (`.github/workflows/watch-apk.yml`) on the runner instead — whenever `watch/**` *or* `hologram/**` changes — and uploaded as `jarvis-watch-<commit>.apk`, unzipped.

There are no tests here because everything with behaviour in it lives in a package that has them — the drawing, the voice tracking, the credentials and the token request are all `hologram/`'s, and all tested there. The one thing that is genuinely this app's and genuinely testable is the **handover protocol** — four spellings of two message paths across two languages and two devices — and that is checked from the phone's side, in `mobile/src/watch-link.contract.spec.ts`, which reads all four out of their sources. It is there rather than here because that is where the other half of the same contract already was.

`android/` is generated by `expo prebuild` and is not committed, exactly as in `mobile/`. Nothing hand-edited there survives.

`build:apk` needs nothing set up first. Every native library this app links comes with its package, so there is no `initialize` here. There used to be one: React Native Skia's prebuilt libraries had to be copied into its package by hand, since postinstalls never run in this repository (`ignoreScripts` in `bunfig.toml`). Jarvis is drawn on the GPU through expo-gl now, so Skia, that step and the workspace task that ran it (`//#install-skia`) are gone.
